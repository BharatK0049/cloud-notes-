# EC2 — Scalability, Elasticity & High Availability

## Core Idea
AWS allows compute capacity to **grow and shrink dynamically** based on demand, ensuring:
- High availability
- Cost efficiency
- No overprovisioning

---

## Key Concepts

### Scalability
- Ability to adjust capacity as demand changes
- Supports growth, seasonal traffic, and unpredictable spikes

### Elasticity
- Ability to **automatically match capacity to demand**
- Scale up during peaks, scale down when idle

---

## Scaling Approaches

### Scale Out (Horizontal Scaling)
- Add **more EC2 instances**
- Work is handled **in parallel**
- Most common and preferred approach in AWS

**Best for:**
- Web servers
- APIs
- Request-based workloads
- Fault-tolerant systems

---

### Scale Up (Vertical Scaling)
- Add more CPU, memory, or storage to an **existing instance**
- Increases power per machine

**Limitations:**
- Doesn’t always improve throughput
- Has upper hardware limits
- Less fault tolerant

---

## Real-World Insight
- Some tasks don’t get faster with bigger machines
- Adding **more workers** often scales better than making one worker stronger
- Different parts of an application may need **different scaling strategies**

---

## Independent Scaling by Layer
- Frontend (request handling) and backend (processing) scale **independently**
- Add capacity only where the bottleneck exists
- Avoids solving one problem by overprovisioning everything

---

## High Availability Design
- Run **multiple EC2 instances** for each role
- Deploy across **multiple Availability Zones**
- Eliminates single points of failure
- Ensures continuous service even during instance or AZ failure

---

## EC2 Auto Scaling

### What It Does
- Automatically:
  - Adds instances when demand increases
  - Removes instances when demand decreases
- Ensures the **desired number of instances** at all times

### Key Benefits
- Handles traffic spikes automatically
- Reduces idle resource costs
- Improves reliability and responsiveness

---

## How Auto Scaling Works

### Metrics Collection
- Performance and application metrics are monitored
- Common metrics:
  - CPU utilization
  - Latency
  - Request count

### Monitoring Service
- **Amazon CloudWatch** collects and tracks metrics

### Scaling Decisions
- CloudWatch metrics trigger scaling actions
- Scaling happens automatically and in real time

---

## Best Practices
- Prefer horizontal scaling over vertical scaling
- Design applications to scale by layer
- Always deploy across multiple AZs
- Use Auto Scaling to match demand continuously

---

## Key Takeaway
**High availability handles failures.  
Horizontal scaling handles load.  
Auto Scaling handles both—automatically.**

Together, they ensure:
- Reliability
- Scalability
- Cost control
