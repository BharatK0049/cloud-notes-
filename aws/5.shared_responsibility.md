# AWS Shared Responsibility Model — Security

## Core Question
Who is responsible for security on AWS?
**Answer: Both AWS and the customer.**

This is known as the **AWS Shared Responsibility Model**.

## Core Principle
- **AWS → Security *of* the cloud**
- **Customer → Security *in* the cloud**

Think of it as a clear division of ownership, not a handoff.

## Analogy (House & Locks)
- The builder constructs strong walls and solid doors.
- The homeowner is responsible for locking the doors.
- AWS builds and secures the infrastructure.
- You decide how securely your workloads run on top of it.

## AWS Responsibilities (Security *of* the Cloud)
AWS is responsible for protecting the foundational layers:

- **Physical infrastructure**
  - Data centers
  - Hardware security
  - Controlled physical access
- **Network infrastructure**
  - Secure networking
  - Traffic isolation
- **Hypervisor layer**
  - Virtualization
  - Isolation between customer workloads

AWS ensures these layers are resilient, monitored, and protected.

## Customer Responsibilities (Security *in* the Cloud)
You are fully responsible for everything you deploy and configure:

### Operating System
- OS access and credentials
- Patching and updates
- User and permission management
- AWS has **no backdoor access**

### Applications
- Application code security
- Vulnerability management
- Secure configuration
- Runtime behavior

### Data
- Data classification (public vs private)
- Access controls (who can see what)
- Encryption (at rest and in transit)
- Compliance requirements (banking, healthcare, etc.)

AWS provides the tools — **you decide how to use them**.

## Encryption & Access Control
- You can restrict data access to:
  - Everyone
  - Specific users
  - A single user
  - No one
- Encryption ensures data remains unreadable even if misconfig
